# تطبيق Android ونشره على Google Play (المرحلة 15)

## البنية

- **Android فقط، ولا تطبيق ويب** (6.10). **Capacitor 8** يشحن الواجهة كلها داخل التطبيق من
  `dist-native/client` (SPA ثابتة يبنيها `npm run build:apk-web`)، فلا يحمّل صفحة من أي نطاق ويب، والاتصال
  الوحيد بالشبكة هو Supabase (البيانات والمصادقة ودوال Edge). معرّف الحزمة `app.zen.quran`، والاسم «زِن»، وminSdk 24 وtargetSdk 36.
- **الإشعارات:** FCM أصلي عبر `@capacitor/push-notifications` (`src/lib/native.ts`)، ويرسلها الخادم نفسه
  دالة Edge `zen-push-dispatch` (`docs/PUSH.md`). زر التفعيل في «التنبيهات والمواقيت».
- **التسجيل الصوتي:** صلاحيتا `RECORD_AUDIO` و`MODIFY_AUDIO_SETTINGS` في `AndroidManifest.xml`، و
  `BridgeWebChromeClient` في Capacitor يحوّل طلب `getUserMedia` إلى طلب صلاحية Android وقت التشغيل،
  فيعمل مسجّل التسميع كما هو بلا شيفرة مكرّرة.
- **المصحف دون اتصال:** الصفحات الـ604 وخطّها داخل الحزمة (`docs/ANDROID_OFFLINE.md`)، والمتن القرآني
  للتسميع والاختبارات مضمَّن في البناء، فلا تنزيل.
- **الحفظ والطباعة:** التصدير يفتح مربع المشاركة (الملفات، Drive…)، وتقارير PDF تفتح مربع الطباعة الأصلي
  ومنه «حفظ بتنسيق PDF» (`ZenPrintPlugin.java`، مسجَّل في `MainActivity`). لا صلاحية تخزين مطلوبة.
- `allowBackup="false"` حتى لا تُنسخ جلسة الدخول في نسخ Android الاحتياطية.

## البناء

```bash
npm ci
# 1) ملف Firebase: Firebase Console ← أضف تطبيق Android بالمعرّف app.zen.quran ← نزّل
#    google-services.json إلى android/app/ (خارج Git).
# 2) بناء الواجهة المضمَّنة (مع المصحف) ومزامنتها مع مشروع Android:
npm run build:apk-web
# 3) افتح Android Studio وابنِ:
npm run android:open      # Build ← Generate Signed App Bundle (AAB)
# أو من سطر الأوامر:
cd android && ./gradlew bundleRelease   # الناتج app/build/outputs/bundle/release/app-release.aab
```

ارفع `versionCode` (و`versionName`) في `android/app/build.gradle` مع كل إصدار.

### مفتاح التوقيع (مرة واحدة)

```bash
keytool -genkeypair -v -keystore android/zen-release.jks -alias zen -keyalg RSA -keysize 4096 -validity 10000
```

ثم `android/keystore.properties` (خارج Git):

```properties
storeFile=zen-release.jks
storePassword=...
keyAlias=zen
keyPassword=...
```

فعّل **Play App Signing** عند أول رفع، واحفظ نسخة من المفتاح وكلمتيه خارج الجهاز. فقدانه يمنع
التحديث إن لم يُفعَّل Play App Signing.

### البناء في CI (المرحلة 6.7)

سير العمل `.github/workflows/android-release.yml` يبني AAB وAPK موقَّعين عند وسم `v*` (أو يدوياً):

1. حدّث عنوان الإصدار الأعلى في `CHANGELOG.md` (مثلاً «— الإصدار 1.4.0»)، وادمجه في `main`.
2. `git tag v1.4.0 && git push origin v1.4.0`. الوسم يجب أن يطابق CHANGELOG وإلا يفشل البناء.
3. `versionCode` = رقم التشغيل + 100، فيزيد مع كل بناء دون تعديل يدوي.
4. الناتج مرفق للتشغيل (30 يوماً) وفي GitHub Release، ومعه `SHA256SUMS`، ويُرفع AAB إلى المسار الداخلي
   في Play إن ضُبط حساب الخدمة (مسوّدة حتى `PLAY_RELEASE_STATUS=completed`).

أسرار GitHub (U8):

| السرّ                       | القيمة                                                          |
| --------------------------- | --------------------------------------------------------------- |
| `ANDROID_KEYSTORE_BASE64`   | `base64 -w0 android/zen-release.jks`                            |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة المخزن                                                     |
| `ANDROID_KEY_ALIAS`         | `zen`                                                           |
| `ANDROID_KEY_PASSWORD`      | اختياري، إن اختلفت عن كلمة المخزن                               |
| `GOOGLE_SERVICES_JSON`      | اختياري، محتوى `google-services.json` (بدونه لا إشعارات FCM)    |
| `PLAY_SERVICE_ACCOUNT_JSON` | اختياري، حساب خدمة بصلاحية Release manager في Play Console (U4) |

استعمل المفتاح نفسه الذي وقّع النسخة المثبّتة (1.3.0)، وإلا لن يُثبَّت التحديث فوقها.

## الصفحات القانونية العامة (تدقيق 2.1)

النصوص في `src/content/legal.ts` (الشاشات تعرضها نفسها). سير «الصفحات القانونية» يولّدها HTML ثابتاً
وينشرها إلى فرع `gh-pages` في مستودع **عام** صغير (Pages غير متاحة لهذا المستودع الخاص على الخطة المجانية):

1. أنشئ مستودعاً عاماً فارغاً، مثل `zen-legal`، وفعّل فيه Settings ← Pages ← Branch: `gh-pages` / root.
2. رمز fine-grained بصلاحية **Contents: Read and write** على ذلك المستودع وحده ← سرّ `LEGAL_SITE_TOKEN` هنا.
3. متغيّرا Actions هنا: `LEGAL_SITE_REPO` (مثل `owner/zen-legal`) و`LEGAL_CONTACT_EMAIL` (بريد الدعم).
4. Actions ← «الصفحات القانونية» ← Run workflow. الروابط في ملخّص التشغيل؛ ضعها في Play Console
   (سياسة الخصوصية، وApp content ← Data safety ← رابط حذف الحساب).

محلياً: `node scripts/build-legal-site.mjs --contact you@example.org` ← `dist-legal/`.

مدة الاحتفاظ المعلنة: الملف الصوتي الخام 90 يوماً ثم يُحذف وتبقى النتيجة (`zen-maintenance`، القاعدة 53).

## نموذج أمان البيانات (Data safety)

| السؤال                             | الإجابة                                                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| هل يجمع التطبيق بيانات أو يشاركها؟ | يجمع؛ لا يشارك مع أطراف ثالثة لأغراض إعلانية                                                                         |
| التشفير أثناء النقل                | نعم (HTTPS فقط، `allowMixedContent=false`)                                                                           |
| طلب حذف البيانات                   | نعم، من داخل التطبيق: الحساب ← بياناتي ← حذف حسابي، أو بطلب من صفحة «حذف الحساب» العامة دون التطبيق                  |
| الاسم / البريد / رقم الهاتف        | مجمَّع، مطلوب لإدارة الحساب، غير مشارَك                                                                              |
| معرّفات المستخدم                   | معرّف الحساب؛ لإدارة الحساب والوظائف                                                                                 |
| التسجيلات الصوتية                  | مجمَّعة عند ضغط «تسجيل» فقط، لوظيفة التسميع؛ تُعالَج لدى مزوّد الذكاء الاصطناعي لتحويلها نصاً (معالجة لا مشاركة)     |
| الرسائل داخل التطبيق               | مجمَّعة (محادثات وغرف الحلقة)، للوظائف                                                                               |
| نشاط التطبيق (التقدّم والدرجات)    | مجمَّع، للوظائف                                                                                                      |
| الموقع                             | **لا يُجمع**: الموقع التقريبي يُقرأ على الجهاز لحساب مواقيت الصلاة فقط ولا يُرسل (معالجة على الجهاز لا تُعلَن جمعاً) |
| معرّفات الجهاز                     | رمز FCM للإشعارات فقط، مرتبط بالحساب ويُحذف معه                                                                      |
| تقارير الأعطال                     | رسالة الخطأ ومساره بلا بيانات شخصية (`client_errors`)، للتشخيص                                                       |
| الإعلانات والتتبّع                 | لا                                                                                                                   |

## تصنيف المحتوى وجمهور التطبيق

- استبيان IARC: تعليمي، لا عنف ولا محتوى جنسي ولا مقامرة؛ فيه **تواصل بين المستخدمين** (محادثات المعلّم
  والطالب وغرف الحلقة بإشراف المعلّم، مع كتم وإبلاغ وحذف).
- **الجمهور المستهدف (القرار 0011، الخيار أ، 1.36.0):** الفئات «5 وأقل» حتى «18 فأكثر»، أي يشمل الأطفال،
  فتنطبق **سياسة العائلات (Families Policy)**. الخطوات في `docs/FAMILIES.md`.
- الصلاحيات الحساسة: الميكروفون (التسميع)، والإشعارات، والموقع التقريبي (زر «موقعي» لمواقيت الصلاة، اختياري، ويبقى
  على الجهاز؛ والدقيق حتى Android 11 فقط). لا صور ولا جهات اتصال.
