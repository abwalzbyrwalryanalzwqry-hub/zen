# القرار 0002: أثر تدقيق للسجل اليومي بعد إغلاقه، يُحفظ سنة

- **التاريخ:** أكتوبر 2026 (خطة التطوير، المرحلة 2، الإصدار 1.18.0؛ الاحتفاظ في 1.21.1)
- **الحالة:** معتمد.

## السياق

السجل اليومي مصدر الحقيقة للحضور والحفظ والتقارير والشهائد. بعد إغلاق اليوم كان يمكن تعديله دون أثر، فلا تعرف
الإدارة ولا وليّ الأمر أن رقماً تغيّر بعد أن رآه.

## الخيارات

| الخيار                                      | المزايا                                         | العيوب                                                           |
| ------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------- |
| أ. منع التعديل بعد الإغلاق                  | بسيط                                            | الأخطاء الحقيقية تبقى؛ المعلّم يعيد فتح اليوم ويعدّل فيضيع الأثر |
| ب. نسخ كاملة للسجل عند كل تعديل             | استرجاع أي نسخة                                 | حجم كبير على الخطة المجانية                                      |
| ج. أثر لكل طالب بقيمتي قبل وبعد عبر مشغّلات | صغير، يلتقط كل مسارات الكتابة (الواجهة والدوال) | يحتاج تنظيفاً دورياً                                             |

## القرار

**ج** (`supabase/migrations/20261208100000_daily_record_audit.sql`): جدول `daily_record_audit` يكتبه مشغّل على
`halaqa_register_entries` والحضور والتقييم بعد `first_completed_at` لليوم، وعملية واحدة لكل طالب في كل معاملة، مع
إعادة الفتح والإغلاق. لا قراءة مباشرة؛ العرض عبر `daily_record_audit_list` لمن يدير الحلقة أو يرى المركز، ومراقب
الحالات الشاذة بصياغة «تستحق نظرة» لا اتهام، وعيّنة أسبوعية للمشرف.

**الاحتفاظ سنة** (1.21.1، `20261212100000_phase_gaps.sql`): `purge_old_record_audit()` يومياً تحذف الأثر وملاحظات
العيّنة الأقدم من 365 يوماً (حدّ أدنى لا يُنقص)، بدفعات حتى 20000 صف. السنة تغطي العام الدراسي وتقاريره ونزاعاته، وما
بعدها لا يفيد إلا حجماً. التقارير تعرض «أيام عُدّلت بعد الإغلاق» من الأثر نفسه.
