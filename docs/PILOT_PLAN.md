## مصفوفة الأجهزة

كل سطر يُجرَّب يدوياً مرة قبل التجربة، وتُسجَّل النتيجة هنا (✅ / ❌ مع رقم المشكلة).

| الفئة         | مثال                                     | Android         | لماذا                                                       |
| ------------- | ---------------------------------------- | --------------- | ----------------------------------------------------------- |
| منخفض الذاكرة | Samsung Galaxy A03 / Tecno Spark (2–3GB) | 11              | الشائع في الحلقات؛ المصحف المضمَّن والتسجيل على ذاكرة قليلة |
| متوسط         | Samsung Galaxy A14 / Redmi Note 12       | 13              | الأغلب؛ الإشعارات مع توفير البطارية في One UI / MIUI        |
| حديث          | Pixel 7 أو أحدث                          | 14–15           | صلاحية الإشعارات (13+)، الصلاحيات الجزئية، الشاشة الكاملة   |
| قديم مدعوم    | أي جهاز                                  | 7.0 (minSdk 24) | أدنى نسخة مدعومة: WebView قديم، الخطوط                      |
| شاشة كبيرة    | جهاز لوحي                                | 12+             | التخطيط والمصحف بعرض كبير                                   |

السيناريوهات على كل جهاز:

1. تسجيل حساب، تسجيل خروج، دخول، استرداد بالرمز.
2. تسميع 60 ثانية ورفعه على شبكة 3G بطيئة (أو محدودة من إعدادات المطوّر) ثم تقييمه من حساب المعلّم.
3. إشعار يصل والتطبيق مغلق ويفتح الصفحة الصحيحة.
4. تنزيل المصحف ثم وضع الطيران: القراءة، العلامات، الورد.
5. تغيير المنطقة الزمنية للجهاز (مثل Asia/Jakarta) ثم تسجيل حفظ بعد منتصف الليل: يظهر في يوم الجهاز (تدقيق 1.1).
6. مشاركة تقرير PDF وبطاقة آية (تغيّر `file_paths.xml` في 1.6).
7. ماسح QR للحضور، وزر «موقعي» لمواقيت الصلاة (Android 11 و12+).
8. تكبير خط النظام إلى الأقصى و TalkBack على الشاشة الرئيسية وشاشة التسميع.

## التجربة

- **المشاركون:** معلّم واحد، 10–20 طالباً، وليّا أمر على الأقل.
- **المدة:** 14 يوماً متصلة، مع جلستين حضوريتين على الأقل.
- **قناة الملاحظات:** مجموعة واحدة مع المعلّم؛ كل مشكلة تُسجَّل Issue في GitHub بتسمية `pilot`.
- **المتابعة اليومية (5 دقائق):** لوحة صاحب التطبيق (الاستخدام، الأعطال، حجم البيانات)، وسجل `zen-push-dispatch`.

## المؤشرات وحدود النجاح

| المؤشر                                            | المصدر                                            | حدّ النجاح                   |
| ------------------------------------------------- | ------------------------------------------------- | ---------------------------- |
| طلاب نشطون يومياً / المسجَّلون                    | `usage_daily` (`app_open`) للموافقين              | ≥ 60% في الأسبوع الثاني      |
| تسميعات مرفوعة لكل طالب أسبوعياً                  | `recitation_sessions`                             | ≥ 3                          |
| نسبة التسميعات المقيَّمة خلال 48 ساعة             | `recitation_sessions` (status، updated_at)        | ≥ 80%                        |
| رفع فاشل                                          | `client_errors` (رسائل الرفع)                     | < 2% من المحاولات            |
| أعطال أصلية                                       | تقارير الأعطال (بموافقة) + Play Console ANR/crash | لا عطل يتكرر لأكثر من مستخدم |
| إشعارات مُسلَّمة                                  | `push_outbox` (sent_at مقابل failed_at)           | ≥ 95%                        |
| أخطاء حرجة مفتوحة (فقد بيانات، تسرّب، تعذّر دخول) | Issues بتسمية `pilot`                             | صفر عند الإغلاق              |
| رضا المعلّم                                       | سؤال واحد في نهاية التجربة (1–5)                  | ≥ 4                          |

**قرار الإنتاج:** كل الحدود محقّقة، أو المخالف منها له إصلاح مدموج وتمت إعادة تجربته على جهاز. يُسجَّل القرار
وتاريخه هنا.
