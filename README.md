# زِن — رفيقك في تعلّم القرآن

منصة تعليمية قرآنية عربية (RTL) تجمع المعلّم والطالب وولي الأمر في تطبيق واحد: محادثات، وحفظ
ومراجعة متباعدة، وتسميع مع تحليل آلي، ومحرّك اختبارات قرآنية، ومحاسبة يومية خاصة، وبوابة لولي
الأمر، وقصص الأنبياء، مع مساعد ذكي.

## التقنيات

**تطبيق Android فقط، ولا تطبيق ويب** (قرار صاحب التطبيق، 28 سبتمبر 2026). React 19 وTanStack Router
وQuery على Vite، تُبنى SPA ثابتة تُشحن داخل تطبيق Capacitor مع المصحف كاملاً · Tailwind CSS 4 ومكوّنات
shadcn/Radix · Supabase (Postgres وAuth وStorage وRealtime ودوال Edge) مع سياسات RLS مختبَرة · إشعارات
FCM · Vitest وESLint وPrettier وPlaywright على حزمة التطبيق نفسها.

## التشغيل محلياً

المتطلبات: **Node.js 22** (انظر `.nvmrc`) وnpm.

```sh
nvm use            # أو ثبّت Node 22 بأي طريقة
npm ci
cp .env.example .env.local   # ثم املأ القيم السرّية
npm run dev
```

## الفحوص

كل طلب دمج يجب أن ينجح فيه ما يلي (وهو ما يشغّله CI):

```sh
npm run typecheck   # الأنواع
npm run lint        # الجودة والتنسيق
npm run test:unit   # اختبارات الوحدات
npm run build       # بناء الإنتاج
npm run test:db     # الترحيلات وفحوص RLS على Postgres مضمَّن
npm run check:types-fresh  # الأنواع مطابقة للترحيلات (أعد توليدها بـ npm run gen:types)
```

## سير العمل

- لكل مرحلة فرع (`feat/phaseN-…` أو `fix/…`) وطلب دمج بالعربية؛ لا دفع مباشر إلى `main` (ثبّت الحارس
  المحلي بـ `npm run hooks:install`، ويرصد سير «حارس main» ما يفلت منه).
- كل جدول أو دالة جديدة يأتي معها فحص RLS في `supabase/tests/checks.sql`.
- المشروع بدأ على [Lovable](https://lovable.dev). أي تعديل من محرّر Lovable يمرّ بطلب دمج مفحوص
  ولا يُكتب على `main` مباشرة (انظر حادثة PR #11 في `CHANGELOG.md`).
