# مجموعة تقييم التسميع الآلي

بوابة قبول قبل تفعيل «تحليل التلاوة» للمستخدمين (تدقيق أكتوبر 2026، المرحلة 3): **اكتشاف ≥ 90%** من التلاوات التي
فيها خطأ، و**إنذار كاذب ≤ 10%** على التلاوات السليمة، على **20 حالة فأكثر**.

## التسجيلات (👤)

- 60 تسجيلاً موصى بها: 20 سليمة و40 فيها خطأ واحد معروف (حذف كلمة، أو إبدال، أو تكرار، أو تقديم وتأخير، أو لحن جلي).
- 6 قرّاء على الأقل بأعمار مختلفة (أطفال وكبار)، وبيئات مختلفة (هادئة، وحلقة فيها ضجيج).
- الوسم (`hasError`) بحكم معلّم متقن، لا بحكم النموذج.
- **الخصوصية:** لا تُرفع التسجيلات إلى المستودع (`audio/` في `.gitignore`)، وتؤخذ بموافقة مكتوبة من القارئ (ومن وليّ الأمر للقاصر).

## الملف `manifest.jsonl`

سطر لكل تسجيل، والمسار نسبةً إلى هذا المجلد:

```json
{"id":"r01","file":"audio/r01.webm","surah":"الإخلاص","from":1,"to":4,"hasError":true,"note":"حذف «أحد»"}
{"id":"r02","file":"audio/r02.webm","surah":"الإخلاص","from":1,"to":4,"hasError":false}
```

## التشغيل

```sh
node scripts/recitation-eval.mjs --self-test          # المقارنة وحدها بأخطاء مزروعة (بلا صوت)
GEMINI_API_KEY=… node scripts/recitation-eval.mjs --out ai-eval/recitation/report.json
```

يشغّل المسار نفسه الذي في الخادم (`runTranscribe`: تفريغ أعمى ثم مقارنة بالنص الموثَّق). جرّب أكثر من نموذج بتغيير
`GEMINI_MODEL` أو `OPENAI_MODEL`، واحفظ التقرير. القرار: إن لم يتجاوز أي نموذج البوابة يبقى التسميع «تسجيل وإرسال
للمعلّم» فقط (أطفئ مفتاح الميزة `recite` من بطاقة «مفاتيح الميزات» لصاحب التطبيق).
